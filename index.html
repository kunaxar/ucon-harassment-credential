Setup guide: gate the quiz to your members, fire one webhook

Exact clicks in Zoho (today) and Monday (where you’re moving). Every step links to the vendor’s own help page.
A · Zoho: restrict to registered members B · Zoho: webhook on submission C · Monday: same two things D · What changes for UCON

A · Zoho: let only UCON-registered people in ZOHO

Zoho gives you three workable ways. Which one fits depends on whether your class roster lives as Zoho users or just as an email list.

Option 1 — Zoho Survey, email-invite-only distribution (best fit for a class roster)

  1. Open the survey → Builder → Publish tab → select your collector (or Add New Collector).
  2. Choose Email distribution and import your UCON member list as contacts (CSV/XLS upload, or add addresses manually).
  3. Send the invites — each registered member gets their own invite link; responses are tied to that contact. Keep the public link unshared so the roster is the only way in.
  4. In Launch → Restrictions → General Restrictions tick “Allow only one response per respondent” so each member completes it once.
Source: help.zoho.com — Distribute surveys using email invites (Private Audience)

Option 2 — Zoho Survey, password protection

  1. Launch → Visibility → set a survey password and share it only with the class roster (email/WhatsApp).
  2. Anyone without the password can’t open the survey. Simple, but the password can be forwarded — fine for a one-day class, weaker for an always-on link.
Source: zoho.com/survey — Send secure surveys (password protection) · Visibility settings

Option 3 — Zoho Forms, share with specific users (only if respondents are in your Zoho org)

  1. In the form builder, open the Share tab → Share With → Specific Users.
  2. Enter the users’ email addresses (they must be users added to your Zoho Forms organization) and send the invite email.
Caveat: Zoho Forms’ “specific users” sharing is built for people inside your Zoho organization — not for an external class roster. For external participants, use Option 1/2, or keep the email-check screen (the first screen of this demo) in front of the quiz: the participant types their email, it’s checked against the UCON-registered list, and only then does the quiz open. That check is the piece BuilderFAX hosts for you.

B · Zoho: fire the webhook when someone submits ZOHO

Zoho Forms (native webhook — recommended home for the quiz)

  1. Open the form → Integrations → Developer & Automation → Webhooks.
  2. Click Configure Webhook.
  3. Webhook URL: the BuilderFAX endpoint (one URL per class).
  4. Content Type: application/json.
  5. Payload Parameters: map the fields BuilderFAX needs — name, email, course, submission time (any form field can be mapped, plus system fields).
  6. Optional: URL Parameters (e.g. a secret key) or Custom Headers so BuilderFAX can tell real submissions from noise.
  7. Save. From then on, every submission POSTs to BuilderFAX instantly and the credential email goes out.
If a submission ever fails to deliver: All Entries → filter dropdown → “Webhooks – Failed Entries” → select → Re-push.
Zoho Forms — the actual Configure Webhook screen (official Zoho help screenshot)
Source: help.zoho.com — Configuring a Webhook (Zoho Forms)

Zoho Survey (if the quiz stays a Survey)

  1. Zoho Survey has no one-click webhook. Use Builder → Hub → Triggers → Trigger Functions — a short Deluge script (invokeurl POST) sends each new response to the BuilderFAX URL.
  2. No-code alternative: connect Zoho Survey to Zoho Flow or Zapier and post “new response” to the BuilderFAX URL.
Source: help.zoho.com — Trigger Functions (Zoho Survey)

C · Monday WorkForms: same two things MONDAY

1 · Gating the form

  1. Open the WorkForm → Share form → Sharing permissions.
  2. Require login restricts the form to logged-in members of your monday.com account — i.e. your staff, not external class participants. It does not fit a member roster.
  3. Enable password protection works for external people, but only on the Enterprise plan.
Caveat: Monday has no native “only these emails may respond” setting for external respondents, and WorkForms has no built-in quiz/scoring — questions are plain form fields. So on Monday the flow stays the same as this demo: the email-check screen in front (hosted by BuilderFAX) verifies the email against UCON’s registered list, then reveals the WorkForm link.

2 · Webhook / automation on submission

  1. Every WorkForm submission creates an item on the form’s board. On that board, click Integrations → Create tab → find the Webhooks integration.
  2. Choose the trigger “when an item is created” and paste the BuilderFAX URL. Monday sends a one-time JSON challenge to the URL; BuilderFAX echoes it back, and the webhook is live.
  3. Each payload carries event.columnValues (the answers — name, email, course) plus pulseName and triggerTime.
  4. Simpler in-platform option: board → Integrate → search WorkForms → recipes like “When form is submitted…” (notify, set date, email) — good for UCON’s own internal alerts; the BuilderFAX credential send uses the webhook above.

D · What changes for UCON

Only two things change: (1) the quiz is gated so only your registered members can open it — email-invite-only in Zoho today, or the BuilderFAX email-check screen in front of the link; and (2) one webhook is added so each submission instantly tells BuilderFAX to issue the named credential to that registered email. Everything else in your class — the content, the session, the roster you already keep — stays exactly the same. And because the credential is issued to the verified email instead of typed into a template, nobody can put someone else’s name on a certificate again.
