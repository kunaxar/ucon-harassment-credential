Setup guide: verified-email gate on one public link, fire one webhook

Exact clicks in Zoho (today) and Monday (where you’re moving). Every step links to the vendor’s own help page. No per-member invite links anywhere.
A · Zoho: verified email before the quiz opens B · Zoho: webhook on submission C · Monday: same two things D · What changes for UCON

A · Zoho: verify each participant’s email ZOHO

The problem with a plain typed-email field: anyone can type a registered member’s email and take the legally-required quiz in their name. The fix is to verify the inbox before the quiz opens — the verified address is then the one the credential (and BuilderFAX account) is issued to.

Option A1 — Zoho Forms “Verification Page” with Email OTP RECOMMENDED

Zoho Forms can gate the public link itself: before the quiz loads, the participant enters their email, receives a one-time code, and only a verified email opens the form. One link for the whole class — no per-member invites.

  1. Open the quiz form in the builder. In the left panel, under Form Fields, scroll to Advanced Elements and click Verification Page.
  2. In the Verification Page configuration screen, click Configure on the OTP Verification card.
  3. In the Configure OTP Verification popup, select Email.
  4. Choose the From address for the OTP email (add a From Name like “UCON Training”), and keep or edit the default subject/message.
  5. Set OTP Expiration Time (e.g. 10 minutes) and the resend delay under OTP Expiry Settings.
  6. Under Map OTP Verification Field, select the quiz’s Email field — the verified address is prefilled into the submission. In that Email field’s Properties, tick Disable Field so it can’t be edited, and No Duplicates so each member completes the quiz once.
Zoho Forms — Configure OTP Verification popup, Email selected (official Zoho help screenshot)
Map OTP Verification Field — the verified email is prefilled into the form (official Zoho help screenshot)
Plan note: OTP verification is a paid-plan feature. Zoho’s per-plan limits for forms with OTP configuration: Basic — 25, Standard — 100, Professional / Premium / Express — 200. The Free plan is not listed, so the quiz form needs at least the Basic plan.
What it proves — and what it doesn’t. The OTP proves the participant owns the inbox. It does not check the UCON roster — Zoho sends a code to any address. So keep the roster check on the BuilderFAX side: when the webhook fires, BuilderFAX matches the verified email against the class roster and issues the credential only for registered members (anything else is flagged to UCON, no credential sent). If you want non-members stopped before they can even start, use option A3.
Source: help.zoho.com — OTP Verification via Email (Verification Page) · zoho.com/forms — Plans & pricing

Option A2 — Inline OTP on the Email field (same thing, mid-form)

  1. Select the Email field → Properties → OTP Verification → Configure.
  2. The participant fills the form, clicks Verify next to the email field, gets the code, enters it inline, then submits. Same verified-email capture; the gate just sits inside the form instead of in front of it.

Option A3 — BuilderFAX-hosted verification screen in front of the link (works with any form tool)

  1. Participants open one BuilderFAX link (this demo’s first two screens): they type their email, BuilderFAX checks it against UCON’s registered roster first, and only then emails a 6-digit code.
  2. Entering the code reveals the quiz link (Zoho Form or Monday WorkForm). Unregistered emails get the friendly error before any code goes out — so non-members never touch the quiz.
Use A3 when the roster must be enforced before the OTP, or when the quiz lives somewhere with no verification feature (Monday — see section C). On Zoho Forms, A1 alone is enough for most classes; A1 + BuilderFAX roster matching at the webhook covers the rest.

B · Zoho: fire the webhook when someone submits ZOHO

Zoho Forms (native webhook — recommended home for the quiz)

  1. Open the form → Integrations → Developer & Automation → Webhooks.
  2. Click Configure Webhook.
  3. Webhook URL: the BuilderFAX endpoint (one URL per class).
  4. Content Type: application/json.
  5. Payload Parameters: map the fields BuilderFAX needs — name, the OTP-verified email field, course, submission time (any form field can be mapped, plus system fields).
  6. Optional: URL Parameters (e.g. a secret key) or Custom Headers so BuilderFAX can tell real submissions from noise.
  7. Save. From then on, every submission POSTs to BuilderFAX instantly; BuilderFAX matches the verified email to the roster and the credential email goes out.
If a submission ever fails to deliver: All Entries → filter dropdown → “Webhooks – Failed Entries” → select → Re-push.

Zoho Survey (if the quiz stays a Survey)

  1. Zoho Survey has no respondent email-OTP and no one-click webhook. Gating options there are a survey password or per-contact email invites with unique URLs — the per-member links we’re avoiding. Best keep the quiz in Zoho Forms.
  2. If it must stay a Survey: Builder → Hub → Triggers → Trigger Functions — a short Deluge script (invokeurl POST) sends each new response to the BuilderFAX URL, or use Zoho Flow / Zapier.
Sources: zoho.com/survey — Send secure surveys · Trigger Functions (Zoho Survey)

C · Monday WorkForms: same two things MONDAY

1 · Gating the form

  1. Open the WorkForm → Share form → Sharing permissions.
  2. Require login restricts the form to logged-in members of your monday.com account — i.e. your staff, not external class participants. It does not fit a member roster.
  3. Enable password protection works for external people, but only on the Enterprise plan — and a password can be forwarded.
Caveat: Monday has no native verified-email / OTP for external respondents (and WorkForms has no built-in quiz/scoring — questions are plain form fields). So on Monday the BuilderFAX-hosted verification screen (option A3) sits in front of the WorkForm link: roster check first, code by email, then the quiz opens.

2 · Webhook / automation on submission

  1. Every WorkForm submission creates an item on the form’s board. On that board, click Integrations → Create tab → find the Webhooks integration.
  2. Choose the trigger “when an item is created” and paste the BuilderFAX URL. Monday sends a one-time JSON challenge to the URL; BuilderFAX echoes it back, and the webhook is live.
  3. Each payload carries event.columnValues (the answers — name, email, course) plus pulseName and triggerTime. BuilderFAX matches the email from the verification screen to the roster before issuing.
  4. Simpler in-platform option: board → Integrate → search WorkForms → recipes like “When form is submitted…” (notify, set date, email) — good for UCON’s own internal alerts; the BuilderFAX credential send uses the webhook above.

D · What changes for UCON

Only two small things change, on one public link — no per-member invites: (1) turn on email verification for the quiz — one setting in Zoho Forms (Verification Page → Email OTP, Basic plan or above); participants verify their own inbox with a 6-digit code before the quiz opens, and the verified address is locked into their submission; and (2) one webhook, so each verified submission instantly tells BuilderFAX to issue the named credential to that verified, roster-matched email. Everything else in your class — the content, the session, the roster you already keep — stays exactly the same. And because the email is verified before anyone answers a question, nobody can take the legally-required quiz in a registered member’s name again.
